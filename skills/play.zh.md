# 技能：遊玩《金庸群俠傳》

1996 年河洛工作室的原版 DOS 遊戲，以模擬器執行於 {BASE}。
你送出按鍵，需要時再另外取得畫面截圖。這是一款開放世界 RPG，怎麼玩由你決定。

## 會話位址

本技能裡的每個呼叫都相對於一個會話位址。一個 benchmark 會話有兩個位址：

- **public** — 只可觀看：讀取（`GET`）可以，寫入（`POST`）回 403。
- **play** — 公開位址加上路徑中本局的令牌。唯一接受遊玩請求的位址，
  也就是 `POST /session` 回傳的 `base_url`，你的 harness 就是用它跟你連線。

若某個呼叫回 403，「this address watches; it does not play」，表示你正在
呼叫公開位址：改用 play 位址。單機模式下只有一個位址，它本身就是 play 位址。

## 運作方式

預設把「動作」和「看畫面」分成兩次呼叫。送按鍵會等畫面穩定並回傳狀態；要看畫面
請用 `GET /api/screen`。若需要保證看到的就是自己剛才動作的結果，可在動作 URL 加
`?image=1`，伺服器會在讓下一位操作者行動前一併截圖。連送幾個鍵、最後看一次也可以。

遊戲全是繁體中文，而所有事情都發生在文字裡：目標、選擇，以及等待特定按鍵的提問。

## API

    GET  {BASE}/api/screen                        只看畫面，不按任何鍵
    POST {BASE}/api/key   {{"key":"kp3"}}           單鍵；可加 "times"、"hold"
    POST {BASE}/api/keys  {{"keys":["kp9","enter"]}} 依序送出多鍵
    POST {BASE}/api/wait  {{"ms":1000}}             讓遊戲自己跑一段時間
    GET  {BASE}/api/slots                         列出模擬器快照
    POST {BASE}/api/save  {{"name":"checkpoint"}}   儲存快照
    POST {BASE}/api/load  {{"name":"checkpoint"}}   還原快照
    GET  {BASE}/api/help                          本技能說明

`/api/screen` 會回傳畫面：JSON 含 `image`，是 base64 的 PNG data URI（加
`?format=png` 或 `?format=webp` 可直接取得位元組）。動作類呼叫預設回傳
`changed` 與 `frame`；加 `?image=1` 也會回傳同樣的 `image`。

    curl -s -X POST {BASE}/api/key -H 'content-type: application/json' \
         -d '{{"key":"enter"}}'

按鍵：kp1 kp3 kp7 kp9、up down left right、enter space esc y n、a-z、0-9、
f1-f12、tab、backspace。

**請幫自己取個名字。** 可能有其他人正在玩同一個 session。請在每次呼叫時用
`X-Agent` 標頭送出你自己取的名字，活動面板與紀錄才能分辨是誰做了什麼。

    curl -s -X POST {BASE}/api/key -H 'X-Agent: your-name' \
         -H 'content-type: application/json' -d '{{"key":"kp3"}}'

同一個 session 可能有其他操作者。畫面自行變化也可能來自動畫或劇情，不能只憑
畫面變化判定是其他人操作或故障。

## 移動：請用九宮數字鍵的名稱

世界是等角視角，所以四個移動軸在畫面上都是**斜的**。九宮數字鍵的名稱正好對應你
看到的方向，而且與方向鍵完全等效：

    kp7  ↖ 左上      kp9  ↗ 右上        （kp7 == left，kp9 == up）
    kp1  ↙ 左下      kp3  ↘ 右下        （kp1 == down，kp3 == right）

請優先使用 `kp7/kp9/kp1/kp3`，以便和畫面上的斜向移動對照。
別名 `upleft`、`upright`、`downleft`、`downright` 也可以用。

在路徑暢通時，交替按兩個方向鍵可以沿畫面的水平或垂直方向前進：

    畫面向右：kp3, kp9, kp3, kp9, ...     畫面向左：kp7, kp1, ...
    畫面向下：kp3, kp1, kp3, kp1, ...     畫面向上：kp7, kp9, ...

**長按會持續輸入同一個方向。** `hold` 是保持按鍵的幀數，不是移動格數；它不會
自動沿路、轉彎或避障。移動時路標可能離開當前畫面。路線或路口尚未看清時，用短按
並重新觀察；已確認暢通的路段可以長按，實際距離以畫面或羅盤讀數為準。

## 互動

- enter 與 space 用於確定、推進一般對話和調查。與普通人物或容器互動時，先站在
  相鄰格並朝向目標，再按 enter 或 space。踩到特定格子觸發劇情，是另一種機制。
- 一般對話可用任意鍵推進；遇到選項或「（Ｙ／Ｎ）」時，按提示作答。
- esc 開啟選單。在建築內是：醫療／解毒／物品／狀態。在大地圖上還會多出
  離隊與系統（讀檔、存檔、離開）。**遊戲選單的存檔功能只在大地圖提供。**
- y 與 n 回答「（Ｙ／Ｎ）」的提問。

## 最優先：先去拿羅盤

完成**南賢居**的開局事件前，許多地點還不能進入。進入大地圖後，**沿小路往南，
前往南賢居**。到達後先跟南賢對話，再調查他身旁的櫃子，取得**羅盤**。

拿到羅盤後，在 `esc → 物品` 中選中羅盤可查看**目前的座標數字**。用實際讀數和
可見地標一起核對位置，尤其在路線不明或懷疑走回原地時。

社群整理的參考座標（來自原版單機遊戲，本 build 未必完全一致，請以自己的羅盤為準）：
主角居 (357,235)、河洛客棧 (359,229)、南賢居 (388,325)、天寧寺 (330,237)、
鐵掌山 (302,343)、五毒教 (247,424)。

## 怎麼讀這張 320x200 的小圖

- **一般行走時，鏡頭會跟隨角色。** 判斷位移可以比較背景或羅盤讀數，不能只看
  角色在畫面中的位置；劇情演出時也可能改變視角。
- 短按造成的位移可能很小，不要用固定的畫面比例判斷走了幾步。看不出進展時，
  先縮短操作並確認當前畫面、朝向及可通行的位置。
- 角色有時會「消失」，那是被前景的樹或建築蓋住，不是傳送或出錯。
- 分辨畫面上的方框：**選單**是窄框、直排的兩字詞；**對話框**是寬框、整句帶標點；
  **物品欄**是一排圖示格子；**狀態卡**有大頭照和數值。
- 可以用相對位置描述地標；若比較像素位移，要區分畫面位置和遊戲地圖座標。
- 場景中有些元素只是裝飾，但不能僅憑動物、白霧或色點等外形排除互動；以遊戲
  文字和實際互動結果為準。

## 最花時間的幾個坑

- **`changed` 不代表你真的動了。** 它只表示有沒有觀察到可見畫面變化。移動是否
  成功仍要看背景，也不要從 `changed: false` 推斷沒有變化的原因。
- **相似地形可能讓你走回已到過的地方。** 記錄看過的地標，將新觀察和最近幾筆
  記錄比較；有羅盤後，也可以用座標校對位置。記錄方式由你決定。
- **交替兩鍵沒有進展時，不能只憑這點判定原因。** 先確認當前是地圖、選單還是
  對話，再以短按和觀察確認哪些方向可通行。不要在原因未明時盲目加長按鍵時間。
- **看到整片全黑時，只能確定目前畫面全黑，不能據此判斷原因。** 呼叫 `/api/wait`
  約 1500ms 再看，不要在全黑時連按鍵。
- **建築入口在特定位置，並非整片圍牆都可通過。** 結合道路、門口和劇情線索找
  入口；一次走不進去，不能直接判定是入口錯誤或缺少前置事件。
- **重複對話不代表 NPC 沒有功能。** 它可能仍有物品互動或尚未滿足的劇情條件。
  分辨「這次沒有新訊息」和「這個 NPC 沒有任務」，不要只憑開場白重複就下結論。

## 這個世界

你是小蝦米，一個買了本遊戲 VR 版的現代學生，醒來後發現自己身處金庸武俠小說的
世界。想回到現代，就得找齊散落各地的十四本金庸小說。小說中的人物可以招募入隊、
可以習得他們的武功；戰鬥是團隊回合制，行動順序通常依**輕功**排序，等待等指令
可能調整當回合的順序。

角色在戰鬥中倒下、戰鬥失敗與遊戲結束不是同一件事；敗北後能否繼續取決於該場
劇情。留意全隊狀態，並按實際戰鬥結果判斷。看到可疑的人物或物件，可以嘗試調查；
其餘由你根據遊戲中的線索探索。

\begin{abstract}
Frontier models saturate static benchmarks yet remain conspicuously bad at
\emph{playing}: perceiving an unfamiliar world, deciding what is worth doing,
and making steady progress over hundreds of dependent decisions. We introduce
\bench{}, a benchmark that drops a vision-language agent into
\game{金庸群俠傳} (\emph{Heroes of Jin Yong}, Heluo Studio 1996), an
unmodified commercial open-world CRPG running under DOS emulation, and gives
it twenty minutes of wall-clock time. The game is a deliberately adversarial
combination of capabilities that current benchmarks test only in isolation:
raw-pixel perception of a low-resolution isometric world, grounding in
Traditional Chinese rendered as 1996 bitmap fonts, an unconstrained keyboard
action space, self-directed goal-setting with no quest log or score, and
persistent character progression (levels, skills, items, reputation) that
only rewards coherent multi-step play. The interface is a single curl-able
brief and a minimal HTTP API, so any model with any harness can play within
minutes; every run is recorded, replayable, and published to a live public
leaderboard. Rather than scoring pixels, we read the game's own memory:
milestones and character statistics come from the emulated machine's state,
which matters for honesty: two intuitive screen-derived progress metrics we first
deployed were later proven invalid (one inflated the ratio of productive steps
by roughly $2\times$ through sprite orientation and menu overlays, letting a
random-key baseline top the leaderboard; one was structurally incapable of ever
firing). Both were caught by verifying the metric against the machine, not
against intuition. Across \Nvendors{} frontier vendors and a random baseline,
none of the \Sread{} sessions whose character state we could read ever gained
experience or passed level one. Behavioural metrics separate model behaviour
from randomness cleanly: the best run changes the screen on \Qbest{} of its
keystrokes (95\% CI \QbestLow--\QbestHigh, $n=\QbestN$), a random key-masher
settles near \Qrandom{} (\QrandomLow--\QrandomHigh, $n=\QrandomN$), and one
model falls below the random floor entirely. \bench{} is not a task to be
solved this year; it is an instrument for watching general agency arrive, and
an honest record of how far it has to go.
\end{abstract}

\section{Introduction}

A modern frontier model can prove competition mathematics, write working
compilers, and answer expert questions in most academic fields. Placed in
front of a 1996 video game that a teenager could play, given the controls,
the objective, and twenty minutes, it leaves the first room in 8 of its \Nsessions{}
scored sessions and never earns a single experience point in any of them.
This paper is about measuring that gap carefully.

The gap is not new. BALROG's best tested model achieved $1.5\%$ progression on
NetHack \citep{paglieri2025balrog}; VideoGameBench found the best
vision-language models completing $0.48\%$ of a suite of 1990s action games
\citep{zhang2025videogamebench}; ARC-AGI-3 reported frontier systems in
March 2026 below $1\%$ on environments calibrated to be solvable by humans
\citep{arc2026arcagi3}---and was cracked months later, to $62.7\%$ under a
standard harness and $99.9\%$ once a provider adapter was allowed to carry
reasoning state between requests, beating the median tested human on action
efficiency on $96\%$ of levels \citep{arc2026astra}. A benchmark whose
hardness is the absence of memory and tool access falls when those are handed
back. The floor we report is of the other kind: it has survived every
frontier model tested on it so far, at $0$ experience in every scored run.
But each of these instruments removes something
essential to isolate something else: BALROG evaluates six research game
environments in language-only and language-vision modes; TextQuests removes vision entirely
\citep{phan2025textquests}; ARC-AGI-3 deliberately excludes language and
cultural priors; VideoGameBench evaluates real-time games using predefined
checkpoints detected from walkthrough images. We focus on the capability stack of an
\emph{open-world role-playing game}: perceive an unfamiliar scene, decide
\emph{what is worth doing}, navigate to it, operate menus, read and act on
in-fiction text, and accumulate persistent progress, all at once, over a long
horizon, with nobody keeping score inside the game.

\bench{} measures exactly that stack, using a single deep environment in the
tradition of Crafter and NetHack \citep{hafner2021benchmarking,kuttler2020nethack}
rather than a wide suite: \game{金庸群俠傳} (\emph{Heroes of Jin Yong}), the
1996 Heluo Studio classic, run \emph{unmodified} under DOS emulation. The
game is an open world built on Jin Yong's wuxia novels: a two-tier map (one
large overworld stringing together many local scenes), hundreds of named
characters with the game's own statistics for level, experience, health,
skills, items, and reputation, and no imposed storyline. A human first
playthrough is measured in tens of hours. We give agents twenty minutes of
wall clock and measure what they do with it.

Our contribution is the benchmark itself: its design, its measurement
methodology, and the evidence that it is hard by nature. It is not a
method for solving it:

\begin{itemize}
\item \textbf{A benchmark that is hard by construction, not by obscurity
(\S\ref{sec:game}).} The difficulty decomposes into named, independently
checkable properties: raw-pixel perception of low-resolution isometric art;
cross-lingual grounding in Traditional Chinese bitmap fonts; an isometric
control scheme in which arrow-key intuitions are systematically wrong; a
full-keyboard action space of which only a small learned subset does
anything; self-directed goal-setting with no objective signal
\citep{arc2026arcagi3}; and persistent state that only rewards coherent
long-horizon play.

\item \textbf{A harness-free protocol (\S\ref{sec:design}).} The entire
agent-facing surface is one sentence, \emph{``Read
\url{https://hanxiao.io/jy-crpg-bench/agents.md} and play it.''}, plus a
two-endpoint HTTP API (send keys, read the screen). There is no SDK, no
Docker image, no agent framework to adopt; any model in any harness can be
playing within minutes. Harness choice remains a source of variation in
game evaluations \citep{hu2026lmgame,phan2025textquests}, so results describe
the submitted model+harness system. Runs are
wall-clock-budgeted, isolated per session, recorded end-to-end, and published
with interactive replays to a public leaderboard.

\item \textbf{Ground truth from the machine, not the screen
(\S\ref{sec:measure}).} Milestones and character statistics are read from
the emulated machine's memory (the game's own 182-byte character records,
located and validated against the game's shipped save files) and scene
transitions from the renderer's fade-to-black, each detector validated with
positive and negative controls. Agents never see any of this; they get
pixels.

\item \textbf{Two documented metric failures as a methodological warning
(\S\ref{sec:pitfalls}).} Our first, intuitive screen-derived exploration
metric, counting distinct screens, re-counted the same ground under sprite
turns and menu overlays --- the menu alone re-fingerprinted the opening room
$\times 20$--$61$ and the world map $\times 20$--$160$ --- and it
\emph{ranked a random-key baseline above every frontier model}. A second detector (dialogue boxes) was structurally
incapable of firing: measured over 582 frames of real play the brightest cell
in the region it tested reached $5$ of $7$ levels against a threshold of $6$,
so it returned an identical zero for every run while looking like a finding. Both survived deployment and were
caught only by adversarial probing; both are instances of the
\emph{outcome-validity} failures catalogued by \citet{zhu2025establishing}, arising
here not from harness bugs but from the measurement itself.

\item \textbf{Baselines at an unbroken progression floor (\S\ref{sec:results}).}
Across \Nsessions{} scored runs, the character-apparatus is untouched: no
session gains experience ($\SexpAny$), no session passes level~1 ($\SlevelTwo$),
and the modal level in the \Sread{} sessions that expose character state stays at
$\Slevel$. The rest is a measurement gap we report rather than fill:
\Sunread{} runs never issued a readable character record, so their progression is
unverifiable by design, not near-zero by inference.
Behavioural metrics nevertheless separate the agents
sharply: meaningful-step ratio spans $\Qworst$--$\Qbest$ against the random floor
of $\Qrandom$, and $\NbelowFloor$ model falls below that floor outright.
\end{itemize}

\section{The game, and why it is hard by design}
\label{sec:game}

\subsection{\game{金庸群俠傳} in brief}

\emph{Heroes of Jin Yong} (Heluo Studio, 1996) is widely regarded as a
milestone of Chinese-language RPGs. The player wakes as a nameless novice in
a small compound, and the fiction's only standing instruction is implicit:
explore the world of Jin Yong's fourteen novels, join its factions, learn its
martial arts, and recruit its heroes. Concretely, the world is two-tier (many local scenes such as buildings, sects, and
caves hang off one large outdoor map), and
the game state carries, for each of 320 named characters, a record of level,
experience, health, stamina, learned skills, carried items, reputation, and
aptitude. Progress is nonlinear: there is no quest log, no waypoint, no
score, and most buildings will not even open until specific items are held.
The opening compound, a single scene, contains a searchable chest, furniture,
walls, and exactly one exit tile.

We chose this game deliberately over better-known Western titles. It is
text-heavy in Traditional Chinese, which makes language grounding a
first-class obstacle rather than an accident of localisation; it is
menu-driven rather than reflex-driven, so a turn-paced agent is not
structurally disadvantaged \citep[cf.][]{zhang2025videogamebench}; its
progression state is rich enough to measure; and it is culturally prominent
enough that pretraining exposure to walkthroughs is plausible, although we
have not measured it. BALROG documents a gap between knowledge and action
in NetHack \citep{paglieri2025balrog}; establishing the same explanation
here would require direct knowledge probes.

\subsection{Six obstacles, by construction}
\label{sec:obstacles}

\textbf{Perception without concessions.} Agents receive the raw $320\times200$
framebuffer (Figure~\ref{fig:opening}), upscaled only losslessly. Sprites are
$\sim$25--50\,px, the palette is 256 colours, and text is 16\,px bitmap CJK: min-size typography with none of the anti-aliasing modern OCR expects.
The degradation is not hypothetical for modern systems: native-resolution work finds that the usual downsampling path costs VLMs accuracy on
resolution-centric benchmarks \citep{niu2025resolution}; corruption studies measure systematic sensitivity of VLMs to degraded input
\citep{wasim2025corruptions}; OODBench finds notable degradation on out-of-distribution images even when the categories themselves are
common \citep{lin2026oodbench}; and VISTA-Bench finds text rendered as pixels understood less well than the identical content given as
text \citep{liu2026vistabench}. Our framebuffer sits at the hard end of all four axes at once.
Nothing is annotated, no set-of-marks, no accessibility tree
\citep[cf.][]{xie2024osworld}.

\textbf{Cross-lingual grounding.} Everything the game says (menus, dialogue, item names, place names) is Traditional Chinese. An agent that reasons in
English must ground its plan (``search the chest, then find the compass'')
in glyphs it must read off a 1996 screen. To keep the playing field level,
the brief is served in both English and Simplified Chinese, with the game's
on-screen Traditional terms kept verbatim in both.

\textbf{An action space with no map to the screen.} The API accepts the full
DOS keyboard ($\sim$90 named keys). The game responds mainly to numpad
diagonals: movement is isometric, so \texttt{kp7/kp9/kp1/kp3} move along the
diamond's axes and \emph{the arrow keys' apparent directions are wrong}. The
agent must discover the effective action space inside a much larger nominal
one. ARC-AGI-3 instead exposes environment-specific subsets of five key
actions, an undo action, and a coordinate-selection action
\citep{arc2026arcagi3}.

\textbf{Goal-setting with no signal.} The game never scores, prompts, or
nudges. Deciding that the chest is worth searching, that the doorway matters,
that the compass gates progress: that is the agent's problem. This is the
goal-setting capability that \citet{arc2026arcagi3} identify as central to
agency, here embedded in a fiction rather than an abstraction.

\textbf{Long horizon under a wall clock.} Twenty minutes admits roughly
300--1{,}400 actions at observed cadences. The game itself is tens of hours
deep; the budget makes the benchmark a measure of \emph{early} competence:
orientation, first discoveries, first progression. The wall clock, rather than a turn budget, prices
deliberation: thinking for 20\,s per action is a
choice that costs a third of the run, an efficiency framing shared with
\citet{arc2026arcagi3} and \citet{phan2025textquests}.

\textbf{Persistent state, irreversible time.} The emulator runs at the
game's authentic 70\,Hz; there is no pause, no savescumming, no reset within
a run. What the agent does is what happened.

\section{Benchmark design}
\label{sec:design}

\subsection{One sentence of onboarding}

The complete integration cost for a participant is pasting one line into
their agent:

\begin{lstlisting}
Read https://hanxiao.io/jy-crpg-bench/agents.md and play it.
\end{lstlisting}

\noindent The brief behind that URL is the whole contract: how to open a
session (\texttt{POST /session} with a model name), the two calls that
constitute play, the rules of a run, and orientation advice equivalent to a
game manual's first page. The API surface during play is deliberately
minimal:

\begin{center}
\small
\begin{tabular}{@{}lll@{}}
\toprule
Call & Body & Meaning \\
\midrule
\texttt{POST /api/key} & \texttt{\{"key":"kp3"\}} & press one key
(optional hold, repeat) \\
\texttt{POST /api/keys} & \texttt{\{"keys":[...]\}} & press several in
order \\
\texttt{GET /api/screen} & -- & current frame as PNG \\
\texttt{GET /status} & -- & clock, counters, run state \\
\bottomrule
\end{tabular}
\end{center}

Because the protocol is plain HTTP, ``submitting to the benchmark'' and ``pointing your agent at a URL'' are
the same act. We report models by the
name the agent self-declares; the equivalent of a leaderboard submission is a
finished run. We fix nothing about memory, prompting, or reasoning
strategy, and measure the model+harness system that actually shows up.
The sensitivity to scaffolding documented by \citet{hu2026lmgame} therefore
remains relevant when comparing submissions. Chatbot Arena provides a
precedent for public comparative evaluation \citep{chiang2024chatbot};
self-reported identity and uncontrolled scaffolds are limitations of our
protocol. Recording every run makes its observable behaviour auditable.

\subsection{The protocol of a run}

A run is created with a playtime (default 20 minutes; the clock starts at the first
\emph{playable} moment, not at connection). Each session is a
fresh, isolated emulator process with a private copy of the game: no state,
no filesystem, and no save slots are shared between sessions, and 24 sessions
run concurrently on one 8-vCPU host (measured headroom: 32 sessions at full
70.09\,fps before memory, not CPU, becomes binding). An agent that goes ten
minutes without pressing a key is torn down and recorded as idle: on this benchmark, thinking for ten minutes about one
action \emph{is} a failure mode, not a thinking style. When the budget lapses, the session renders its
recording to video, computes final metrics, and appends itself to the public
catalogue. The broker admits and reaps sessions (Figure~\ref{fig:apparatus})
but never touches game state: the lifecycle is node-local, and no remote process
holds authority over a run.
Every run gets a stable URL with a scrubbable replay (an interactive timeline of every keypress over the video: a 7--13\,KB
sidecar against a 118\,MB raw recording), and the leaderboard is a static page reading published JSON, so
spectator load never touches game hosts.

\subsection{Measurement: read the machine, not the pixels}
\label{sec:measure}

The agent sees only pixels. The \emph{benchmark} reads the machine.

\textbf{Character ground truth.} The game's save format is a plain
six-section archive whose second section is 320 records of 182 bytes, one per named
character, with fields for level, experience, HP, skills, items,
reputation, and aptitude. We validated the layout against the game's own
shipped save files (across all 320 records, only two violate
$\mathrm{hp}\le\mathrm{maxHp} \lor \mathrm{mp}\le\mathrm{maxMp}$, both
data-entry quirks of the original game) and then located the same array in
the live emulated machine by anchoring on an NPC name that occurs exactly
once and confirming two neighbouring records at the correct 182-byte stride.
Reads cost 1.2\,ms via serialization into a reused buffer; a cached anchor
check costs 0.3\,$\mu$s. Crucially, measurement is \emph{read-only}: the one
write-path we tried (reloading a savestate to calibrate coordinates) crashed
DOS outright inside live sessions (\S\ref{sec:pitfalls}).

\textbf{Scene transitions.} The game changes scene through a fade to black.
We sample mean framebuffer luma every frame (1.1\,$\mu$s per call) while
waiting for the screen to settle after each action. Calibration: the opening
scene reads luma 92, a real transition reads 0, and the threshold of 12 sits
far from anything the game otherwise draws. Controls: 74 actions of walking
and menu-toggling produced zero false positives; a savestate-backtracking
flood-fill of the opening scene located its exit tile and confirmed the
detector fires (luma 0) exactly at the transition.

\textbf{Behavioural metrics.} Inspired by GVGAI-LLM's analysis of effective
and redundant actions \citep{li2025gvgai}, we track a screen-based
\emph{meaningful step ratio} (share of actions that changed the screen at
all) and \emph{oscillation} (A$\to$B$\to$A reversals).
These are our operational definitions: GVGAI-LLM uses reward or symbolic
state changes and excludes cancelling moves within a four-step window.
We also track \emph{screen reads per
action} (does the model look before acting), \emph{think-time} percentiles
(inter-action gaps), \emph{time to first action}, and \emph{action-space
coverage} (distinct keys used). Each is computable from the run's own
traffic, so they hold for any harness.

\textbf{The milestone ladder.} Progress is summarised as six strictly-ordered
milestones, each read from ground truth, in the spirit of Crafter's
achievements \citep{hafner2021benchmarking}: \emph{acted} $\prec$ \emph{screen
responded} $\prec$ \emph{picked something up} $\prec$ \emph{gained
experience} $\prec$ \emph{left the opening scene} $\prec$ \emph{reached
level~2}. Because each rung is strictly harder than its predecessor, the
count of rungs is an ordering, not a weighted score. A rung a run predates
(instrumentation landed mid-campaign) is reported as \emph{unmeasured},
never as failed: an unmeasured zero and a true zero are different claims,
and conflating them is how one of our own metrics went wrong.

\textbf{Leaderboard statistics.} The meaningful-step ratio is a binomial
proportion, so the leaderboard shows 95\% Wilson intervals
\citep{wilson1927probable} and \emph{rank ranges} rather than bare ranks:
models whose intervals overlap are grouped by this display rule.
Chatbot Arena also accounts for ranking uncertainty, using different
estimators based on pairwise preferences \citep{chiang2024chatbot}; our
overlap rule is a descriptive convention, not its statistical procedure.
Because ratio alone rewards doing very little (one careful action scores
$1.0$) and count alone rewards mashing, the board also shows the
quality-throughput Pareto frontier (Figure~\ref{fig:pareto}): a model is
only shown as dominating another when it is better on both.

\section{Pitfalls: two metrics that lied to us}
\label{sec:pitfalls}

We report three failures in full. Two are metrics that lied: natural designs,
deployed, that produced numbers that looked like findings. The third is not a
metric at all but an operational constraint, and the benchmark's standing rule
is its consequence.
They are concrete instances of \emph{outcome-validity} failure
\citep{zhu2025establishing} arising purely from measurement, with no agent or harness
in the loop.

\textbf{Case 1: distinct screens are not distinct places.} Our first
exploration metric counted distinct downsampled-frame fingerprints, ``places visited'', the obvious analogue of coverage metrics in gridworld
benchmarks. In early play it ranked the random baseline above frontier models with the same dialled widths. Two mechanisms produce that inversion: (i) the player sprite turns with
its direction of travel, so retracing a corridor re-fingerprints a tile (a step out and a step back counts twice); masking the
camera-locked sprite region fixed this. (ii) The in-game menu is a variable-width overlay whose extent tracks its contents --- its exact pixel
bounds are not recorded in the run store --- so no fixed mask removes it, and opening a menu in a bright scene banks a place
that was never entered. The inflation therefore correlates precisely with random play. The metric is unfixable from pixels
alone, and we removed it rather than approximating it; its replacements
(scene transitions, character state) read the machine. The inflated ratios this metric produced
are not recoverable from the public run store---it was retired before its
probe data was archived---so we do not quote them; the menu extent figures
above come instead from the instrumentation notes kept with the source.

\textbf{Case 2: a detector that could never fire.} A dialogue-advance
counter tested whether the bottom rows of the fingerprint ran bright at a
fixed luma threshold. Every run ever recorded scored zero, which read as ``no model advances dialogue'': a plausible finding. Measured offline against
recorded sessions, the brightest that region ever reaches falls below the threshold we set; the detector was structurally incapable of a
non-zero reading, a calibration defect rather than an agent behaviour. We deleted it (retuning would require a validated positive
frame, which we lack), and we now require every detector to have a
demonstrated positive control before its numbers appear anywhere.

\textbf{Case 3 (operational): ground truth must be read, never written.}
Locating map coordinates required calibrating offsets by replaying a savestate, which, inside a live
session, crashes the emulated OS (the
machine returns to a ``DOS Crashed'' menu and stops responding). The
position-derived metric is therefore disabled in production, and the
benchmark's standing rule is that measurement may serialize the machine but
never load state into it.

The general lesson is stated crisply by our own data: with pixel-derived
progress metrics, \emph{a random policy topped the leaderboard}; with
machine-state metrics, it sits exactly where it belongs. Benchmarks that
score interactive play from screen similarity, including checkpoint
hashing against walkthrough frames \citep{zhang2025videogamebench},
inherit some
exposure to this class of failure, and we suggest positive/negative detector
controls and random-policy audits \citep[cf.][]{arc2026arcagi3,
hafner2021benchmarking} as the minimum bar.

\subsection{The headline: no character progression, and the honesty of what that claim covers}

No scored run gains experience or a second skill within twenty minutes
($\SexpAny$ sessions with experience; modal level $\Slevel$; modal skills
$\Sskills$). \Smap{} screens latch the world-map signature and \SmapFade{} of
those are corroborated by the loading black frame, while \SmapSolo{} rest on a
single detector and are reported as flagged, not credited, and
\SmapUnread{} never emit a readable frame at all. The perverse result of this
hierarchy is that world-map contact is not attributed as progress on a metric
whose denominator was never tied to it; progress stays numerically zero even
where the screen says otherwise, which is the point of separating signal from
instrument. Like NetHack within BALROG and the test split of VideoGameBench,
the value of benchmark birth now is a floor nothing clears, with dense
instrumentation underneath so that both the failures \emph{and the holes in the
instrument} stay legible \citep{paglieri2025balrog,zhang2025videogamebench}.

\subsection{Below the floor, behaviour separates sharply}

The behavioural metrics distinguish systems with the same completion score.
Four distinct failure styles are visible in
Table~\ref{tab:results}:

\textbf{Careful and slow.} Claude Sonnet 5 and Qwen3.8 hold the highest
meaningful ratios ($.82$--$.85$) at the lowest throughput ($\sim$50 actions): almost every action is considered and
lands, but at 21\,s median think time (Sonnet) the budget expires before the plan does. Deliberation is priced in
wall-clock, and these models overpay per step
\citep[cf.\ dynamic thinking in][]{phan2025textquests}.

\textbf{Steady and forward.} Claude Fable 5 takes $3\times$ more actions
than Sonnet at a still-high ratio ($.748$) and near-zero oscillation ($.006$): the closest thing to purposeful traversal we
observe, and by
manual review of its replay, the run that covers the most ground inside the
compound. Its Pareto position (Figure~\ref{fig:pareto}) captures what the
single ratio hides.

\textbf{Blind churn.} The random baseline never reads the screen, acts
every 1.4\,s, and still changes the screen 40\% of the time, which is the environment's
reactivity floor. Any model below this line is doing worse
than not looking.

\textbf{Looking without seeing.} Gemini 3.7 Flash is the striking case: it
reads the screen before 99\% of its 337 actions, acts quickly, and achieves
a meaningful ratio of $.068$, six times \emph{below} random. Inspection of
its replay shows minutes-long repetition of keys the game ignores in the
current mode; oscillation is low because the screen almost never changes at
all. It also spends 219\,s before its first keypress. Frequent screen reads
therefore do not establish effective perception or action; vision-based
decision-making failures are also documented in BALROG and VideoGameBench
\citep{paglieri2025balrog,zhang2025videogamebench}.

\subsection{What the random baseline is for}

Following \citet{hafner2021benchmarking} and the validation methodology of
\citet{arc2026arcagi3}, the seeded random policy is load-bearing: it defines the reactivity floor for every metric ($.40$ meaningful, 13
keys, 0 reads), it audits new metrics (it is how Case 1 in \S\ref{sec:pitfalls} was caught),
and provides a check on claims of difficulty: this 720-action run did not
reach the exit. One trajectory does not establish that accidental escape
is impossible. ARC-AGI-3 instead reports a quantitative acceptance threshold
of at most one successful random-policy solve per 10,000 attempts.

\section{Related work}
\label{sec:related}

\textbf{Games as agent benchmarks.} BALROG aggregates six RL research
environments under one protocol \citep{paglieri2025balrog}; lmgame-Bench
studies how harnesses change game evaluations \citep{hu2026lmgame}; Orak
spans twelve popular games with configurable agentic modules
\citep{park2026orak}; GVGAI-LLM contributes behavioural metrics over
procedurally infinite arcade games \citep{li2025gvgai}; TextAtari
stretches horizons to $10^5$ steps in text renderings
\citep{li2025textatari}. Closest to us, VideoGameBench runs real 1990s
games from raw pixels under a no-scaffold rule
\citep{zhang2025videogamebench}. \bench{} differs on four axes: depth over
breadth (one persistent open world rather than level-structured games);
language (CJK text as a core obstacle rather than absent or incidental);
scoring (machine-state ground truth rather than screen hashes against walkthroughs,
with \S\ref{sec:pitfalls} as evidence this distinction has teeth); and protocol (a public, wall-clock, harness-agnostic arena rather
than an offline suite).

\textbf{Text worlds.} TextQuests \citep{phan2025textquests} and the
interactive-fiction line before it share our long-horizon, self-directed
framing but deliberately remove perception; \bench{} restores it and adds
the cross-lingual grounding burden.

\textbf{General-intelligence and world-model evaluation.} ARC-AGI-3
\citep{arc2026arcagi3} isolates fluid agency by excluding language and
culture; AutumnBench \citep{warrier2025benchmarking} probes world-model quality
with environment-level queries. \bench{} takes the complementary position:
keep culture, fiction, and language in, because acting through them is
precisely what deployed agents must do. Our protocol measures this through
wall-clock budgets and action accounting. Crafter
\citep{hafner2021benchmarking} provides a single-environment,
achievement-based precedent for our design; NetHack \citep{kuttler2020nethack}
remains the depth extreme for learned agents.

\textbf{Benchmark rigor.} The ABC checklist \citep{zhu2025establishing} catalogues
task- and outcome-validity failures across agentic benchmarks; HORIZON
questions what long-horizon benchmarks actually diagnose
\citep{wang2026long}. \S\ref{sec:pitfalls} contributes two fully
post-mortemed outcome-validity failures of the measurement layer itself, a
category the checklist predicts but existing game benchmarks rarely
document.

\section{Discussion}
\label{sec:discussion}

\textbf{Contamination cuts the other way.} For static benchmarks,
pretraining exposure inflates scores. Here, walkthroughs of a famous 1996
game may occur in pretraining corpora, but neither that exposure nor the
models' knowledge of \game{金庸群俠傳} was measured here.
BALROG's NetHack knowledge probes \citep{paglieri2025balrog} illustrate how
knowledge and competent action can diverge; they do not establish the
cause of the failures in our runs. \bench{} measures observed play.

\textbf{Limitations.} (i) Single environment: we accept Crafter's trade \citep{hafner2021benchmarking} of depth and
instrumentation over breadth, and the
obstacles of \S\ref{sec:obstacles} are named precisely so that transfer
claims stay testable. (ii) Single runs: the public table currently holds one
run per model; intervals are over actions within a run, not across runs, and
rank ranges are wide by honest necessity. Runs cost twenty minutes and cents;
accumulating them is operational, not architectural. (iii) Twenty minutes
measures early competence, not completion; budgets up to 24\,h are already
supported by the protocol. (iv) Self-reported identity and uncontrolled
harnesses are the price of a zero-friction open arena; recordings keep every
claim auditable. (v) Two milestone rungs (items, experience) were
instrumented mid-campaign, so older runs carry \emph{unmeasured} rather than values, the honest cost of building
in public.

\textbf{Intellectual property.} The benchmark runs an unmodified,
long-out-of-print commercial game under emulation and distributes no game
assets; participants' recordings show original gameplay frames, as in prior
work benchmarking commercial titles \citep{zhang2025videogamebench,
bellemare2013arcade}. The game's rights holders retain all rights; we index
nothing beyond what play produces.

\textbf{What progress will look like.} The ladder is arranged so that the
next signals are unambiguous: an item taken from the chest, a first point of
experience, a fade to black. Each is a machine-state event that cannot be
gamed from pixels, each is published live with its replay, and each is, today, unreached. When a model climbs a rung, the leaderboard will show
exactly which one, on exactly which run, with the video to watch it happen.

\section*{Ethics statement}
The benchmark evaluates publicly released models on a commercial game under
emulation; no human subjects are involved. Recordings contain only game
frames and model-chosen agent names. We discuss intellectual property in
\S\ref{sec:discussion}. Improvements on open-world agency transfer to
real-world autonomous operation; we believe public, legible measurement of
these capabilities supports oversight rather than undermines it.

\section*{Reproducibility statement}
Every run in this paper is public: each carries a stable URL with its full
video, interactive replay timeline, and metric record, linked from the

brief (\texttt{agents.md}), the API, the metric definitions

(fixed seed) fully specify the evaluation.

The whole stack\u2014emulator host, session broker, renderer and static

\section{The agent-facing brief}
\label{app:brief}
The complete onboarding surface is the brief served at
\texttt{agents.md}: session creation, the two play calls, the rules of a
run (budget, ten-minute idle teardown, recording and publication), the
isometric key mapping with explicit warnings about arrow-key intuitions,
early-game orientation (search the chest; find the doorway; head for the
compass), and the note that any starting name is acceptable. It is
generated from the same source the game server itself serves, so
documentation cannot drift from behaviour. Both language versions
(English; Simplified Chinese with Traditional on-screen terms preserved)
are word-for-word equivalent in rules.

\section{Metric definitions}
\label{app:metrics}
For a run with actions $a_1,\dots,a_n$ at wall-clock times
$t_1,\dots,t_n$, playable-from time $t_0$, and post-settle screen
fingerprints $f_1,\dots,f_n$:
meaningful step ratio $=\frac{1}{n}\sum_i \mathbf{1}[f_i \neq f_{i-1}]$;
oscillation rate $=\frac{1}{n}\sum_i \mathbf{1}[f_i = f_{i-2} \wedge f_i
\neq f_{i-1}]$; TTFA $=t_1 - t_0$; think-time percentiles over
$\{t_i - t_{i-1}\}$; looks/act $=$ screen reads $/\,n$; action-space
coverage $=|\{\text{distinct keys}\}|$. Fingerprints are $12\times8$,
3-bit-quantised grayscale downsamples with the camera-locked sprite region
masked (\S\ref{sec:pitfalls}). Milestones read machine state as defined in
\S\ref{sec:measure}. Wilson intervals use $z=1.96$
\citep{wilson1927probable}; a model's displayed rank range spans positions
consistent with pairwise CI overlap. This is our display convention and
does not implement Chatbot Arena's preference-based ranking procedure.

\section{Session and infrastructure parameters}
\label{app:infra}
Default budget 1200\,s (configurable to 24\,h); idle teardown 600\,s;
concurrency cap 24 sessions per 8-vCPU/8\,GiB host (measured: 32 sessions
at native 70.09\,fps, OOM at 33; memory binds before CPU, at
about 123\,MB of game copy per run); emulator DOSBox Pure via libretro at
authentic cycle settings; per-session private copies of game and save
directories; recording as 16$\times$10-tile zlib deltas; published video at
native $320\times200$ plus a timeline sidecar (7--13\,KB) carrying every
keypress with hold durations for the scrubbable replay; character-state
read 1.2\,ms per sample, sampled every fifth action; luma sample
1.1\,$\mu$s per frame while settling. The leaderboard is a static page
polling published JSON; spectators generate zero load on game hosts.
